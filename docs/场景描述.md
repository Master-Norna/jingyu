# 场景描述（`jingyu.scene.v1`）

场景描述是一张图的唯一事实来源：一个 JSON 文档，写明世界、材质、物体、灯光、相机和
渲染设置。它是声明式的，可以版本化、比较和局部修改；图像里的每个像素都能通过 ID 遮罩
追回到这里的某一条。

完整的机器可读定义是 [`schemas/scene.v1.schema.json`](../schemas/scene.v1.schema.json)
（由生成器注册表生成）；各几何算子、材质族和环境族的参数见 [生成器目录](生成器目录.md)。

## 约定

| 项 | 约定 |
|---|---|
| 长度 | 米，字段名不带后缀 |
| 角度 | 度，字段名不带后缀；旋转是 XYZ 欧拉角 |
| 其他单位 | 写进字段名：`power_w`（瓦）、`lens_mm`（毫米）、`sensor_width_mm` |
| 坐标系 | 右手系，Z 向上 |
| 物体原点 | 底面中心：`location` 的 z = 0 就是放在地面上（平面以中心为原点） |
| 颜色 | sRGB 十六进制 `#rrggbb`，进入 Blender 前转换为线性 |
| id | `^[a-z][a-z0-9_-]{0,62}$`，最长 63 个字符（Blender 名字上限） |
| id 命名空间 | 材质一个命名空间；编组、物体、灯光、相机共用一个命名空间 |

未写的可选字段会按 Schema 默认值补全；补全后的“规范化场景”才是渲染和哈希的对象。
未知字段一律拒绝（`additionalProperties: false`），拼错的字段不会被悄悄忽略。

## 顶层结构

```json
{
  "schema": "jingyu.scene.v1",
  "id": "minimal-vase",
  "title": "One vase on a floor",
  "intent": "可选，一句话写明这张图要让人看到或感到什么",
  "notes": "可选，给人看的说明",
  "world": {"environment": {"family": "daylight", "sun_elevation": 12}},
  "materials": [ ... ],
  "groups": [ ... ],
  "objects": [ ... ],
  "lights": [ ... ],
  "cameras": [ ... ],
  "render": { ... }
}
```

`schema`、`id`、`cameras`（至少一台）和 `render` 必填。

`intent` 不影响渲染，是看图时的对照：每一轮先用一句话说出图里实际是什么，再和
`intent` 比。

## 世界：环境族

场景外面的光来自**环境族**，和几何算子、材质族一样是带参数的生成器，`family` 是判别
字段：

```json
"world": {"environment": {"family": "daylight", "sun_elevation": 12, "sun_azimuth": 160,
                          "cloud_cover": 0.2, "haze": 2}}
```

| 环境族 | 用途 | 主要参数 |
|---|---|---|
| `daylight` | 户外日光，从黎明到黄昏、从晴到阴；窗外进来的光也来自这里 | `sun_elevation`、`sun_azimuth`、`cloud_cover`、`haze`、`ground_color` |
| `uniform` | 各方向相同的光：中性影棚、纯色背景 | `color`、`strength` |

环境族负责让彼此必须一致的量保持一致：`daylight` 由太阳高度推出阳光色温（低太阳偏暖），
由云量推出阳光强弱和阴影软硬，天空用物理散射模型，地平线以下是被同一片光照亮的地面。
模型只描述“几点、什么天气”，不用自己拿几盏灯去模仿太阳。

没有 `environment` 时，世界是 `color` 在 `strength` 下的均匀光（等同于 `uniform`）。

## 编组与放置关系

描述关系，而不是逐个算坐标：

```json
"groups": [{"id": "still_life", "location": [0.2, 0.3, 0], "rotation": [0, 0, 8]}],
"objects": [
  {"id": "top", "geometry": {"op": "box", "size": [1.2, 0.75, 0.04]}, "rest_on": "leg_a"},
  {"id": "bowl", "parent": "still_life", "geometry": {"op": "vessel"}, "rest_on": "top"},
  {"id": "orange", "parent": "still_life", "geometry": {"op": "sphere", "radius": 0.04},
   "location": [0.02, 0, 0], "rest_on": "bowl"}
]
```

- **编组**（`groups`）是不可见的变换，有 `location`、`rotation` 和统一缩放 `scale`；
  编组可以再属于编组。物体、灯光、相机和编组都可以写 `parent`，它们的位置和旋转就相对
  于这个编组，挪一个编组就挪动整组东西。`look_at` 永远是世界坐标里的点。
- **放在…上**（`rest_on`）：物体保持给定的世界 x、y，高度由景语算出，让它最低处正好
  落在支撑物正下方最高的表面上：桌面、碗底、另一件东西的顶上。支撑可以连环（橘子在碗里，
  碗在桌上），按依赖顺序求解。支撑物下方没有这件物体、或者支撑形成环，报
  `spec.placement_failed`。在倾斜的编组里，它沿世界竖直方向落下。

## 材质

每个材质是一个材质族加参数，`family` 是判别字段：

```json
{"id": "glaze", "family": "ceramic", "color": "#6f93b3", "gloss": 0.9}
{"id": "pot", "family": "metal", "metal": "copper", "polish": 0.72}
{"id": "bottle-glass", "family": "glass", "tint": "#9cd3a8"}
```

现有材质族：`ceramic`、`glass`、`metal`、`plastic`，以及直接写 Principled 通道的
`principled`。材质族的参数是面向创作的（光泽、抛光、磨砂），族内部负责把它们映射成
物理上合理的渲染通道。

## 物体

```json
{
  "id": "vase",
  "geometry": {"op": "vessel", "height": 0.3, "base_radius": 0.045, "belly_radius": 0.085,
               "belly_at": 0.3, "neck_radius": 0.022, "neck_at": 0.9, "lip_radius": 0.03},
  "material": "glaze",
  "location": [0, 0, 0],
  "rotation": [0, 0, 0],
  "scale": [1, 1, 1],
  "visible": true
}
```

`geometry.op` 是判别字段，选择几何算子：`box`、`plane`、`sphere`、`cylinder`、
`cone`、`lathe`（任意旋转体轮廓）、`vessel`（器皿）、`wall`（可开门窗洞的墙）。省略
`material` 时用中性灰。物体还可以有 `parent` 和 `rest_on`，见上一节。
`visible: false` 让物体留在场景里但不参与渲染。

## 灯光

`kind` 是判别字段：

| kind | 专有参数 |
|---|---|
| `point` | `power_w`、`radius` |
| `spot` | `power_w`、`radius`、`spot_size`、`blend` |
| `area` | `power_w`、`size`，可选 `size_y`（矩形，比如窗形软光） |
| `sun` | `strength`、`angle` |

所有灯都有 `location` 和 `color`；写了 `temperature_k`（色温，开尔文）就用色温代替
`color`，比如 2700 暖光灯泡、5500 正午日光。灯和相机可以有 `parent`。有方向的灯用 `look_at`（看向一个点，上方保持 +Z）
或 `rotation`（欧拉角）二选一。

## 相机

```json
{"id": "main", "location": [0, -2.3, 0.3], "look_at": [0, 0, 0.13], "lens_mm": 45}
```

`look_at` 与 `rotation` 二选一，可以有 `parent`。其余字段：`projection`（`perspective` /
`orthographic`）、`lens_mm`、`sensor_width_mm`（传感器宽度，水平适配）、
`ortho_scale`、`clip_start`、`clip_end`、`shift`。

## 渲染

| 字段 | 默认 | 说明 |
|---|---|---|
| `camera` | 必填 | 通过哪台相机渲染 |
| `resolution` | `[1280, 720]` | 宽、高（像素） |
| `engine` | `cycles` | `cycles`（路径追踪）、`eevee`（实时，需要 GPU 或软件 OpenGL）、`workbench`（预览着色） |
| `samples` | `64` | 每像素采样数 |
| `denoise` | `true` | Cycles 降噪 |
| `device` | `auto` | `auto` 有可用 GPU 就用 GPU |
| `seed` | `0` | 固定采样种子，保证可复现 |
| `view_transform` | `agx` | 色调映射：`agx`、`standard`、`filmic`、`khronos_pbr_neutral` |
| `exposure` | `0` | 曝光（档） |
| `transparent_background` | `false` | 背景透明 |

`render_scene` 的 `preview` 质量档把分辨率减半、采样封顶 16，`final` 按场景原样渲染。

## 校验结果

`validate_scene` 返回全部问题，每条都有稳定的 `code`、指向字段的 `pointer`、
`message` 和可能的 `hint`。例如：

```json
{"code": "spec.invalid_parameter", "severity": "error",
 "pointer": "/objects/1/geometry/neck_at",
 "message": "vessel: require 0 < belly_at < neck_at < 1"}
```

警告（`severity: "warning"`）不阻止渲染：

- `spec.scene_unlit`（没有任何光）、`spec.empty_scene`（没有可见物体）；
- 物理检查：`physics.intersection`（一件东西陷进另一件超过 1 毫米）、
  `physics.floating`（悬在下方物体上空超过 2 毫米），提示里给出可以用的 `rest_on`；
- 渲染后的画面检查，写进回执：`frame.not_visible`（可见物体一个像素都没占到）、
  `frame.underexposed`（整体偏暗，提示建议的曝光值）、`frame.overexposed`（大片死白）。

全部错误码见 [错误码](错误码.md)。

## 局部修改

`edit_scene` 用操作而不是重写来改场景：JSON Patch（`add`、`remove`、`replace`、
`move`、`copy`、`test`）加 `merge`（把一个对象合并进目标）。路径里的 `@<id>` 按 id 选中
数组元素：

```json
[{"op": "replace", "path": "/groups/@still_life/location/0", "value": 0.35},
 {"op": "merge", "path": "/world/environment", "value": {"sun_elevation": 8}}]
```

一组操作要么全部生效，要么报 `patch.failed` 且什么都不改。`diff_candidates` 用同样的
`@<id>` 路径列出两个候选之间的场景变化，以及每个物体在画面里的位置和面积变化。
