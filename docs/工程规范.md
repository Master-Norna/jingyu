# 工程规范

这份规范约束景语的代码、协议和数据。它的目的只有一个：让模型和人都能**看懂、定位、
修改、复现**每一张图。条目后的括号注明由什么守住；没有自动检查的条目靠评审。

## 1. 命名与语言

- Python 模块、函数、JSON 字段、id、错误码、工具名一律 ASCII 英文。
  文档和文档文件名可以用中文。
- 代码注释、docstring、工具和参数的描述用英文：这些文字会原样出现在 Schema 和工具
  目录里，给模型读。
- 工具名、生成器名是 `snake_case`；错误码是 `分组.名字`；协议 id 是
  `jingyu.<名字>.v<主版本>`。

## 2. 分层与依赖方向

分层见 [架构](架构.md)。依赖只能自上而下：

- 纯核心（`errors`、`canonical_json`、`conventions`、`generator`、`idmask`、
  `geometry/`、`materials/`）只用标准库，因为 Blender 内也要运行它。
- `blender/` 只用纯核心和 bpy / bmesh / mathutils，不做校验。
- 只有 `mcp_server.py` 导入 mcp。

（`tests/test_import_boundaries.py` 静态检查）

## 3. 失败要明确，不静默替代

- 找不到、不支持、不合法时明确失败，不换一个“差不多”的东西继续。比如请求的渲染引擎
  不可用就报 `blender.engine_unavailable`，不悄悄换成另一个引擎。
- 跨越进程或工具边界的失败都带 `ERROR_CODES` 里注册过的 `code`；未注册的码在构造
  时就抛错。（测试扫描源码里出现的每个错误码）
- 校验问题一次全部报出，每条带 JSON Pointer；能给修改建议的带 `hint`。
- 警告只用于不影响正确性的情况（无光、空场景），并随候选回执保存。
- 错误码只加不改：已发布的码不改名、不改含义。

## 4. 协议与数据格式

- 每种持久化或跨进程的文档都有版本 id：`jingyu.scene.v1`、`jingyu.worker.v1`、
  `jingyu.receipt.v1`、`jingyu.id-map.v1`。不兼容的改动升主版本，并写迁移说明。
- 解析一律严格：重复键、NaN、Infinity 拒绝；未知字段拒绝。
- 所有 JSON Schema 校验都经过 `jingyu/schema_validation.py`，正则按 ECMA-262 语义匹配，
  和其他语言的校验器结果一致。
- 内容身份用规范 JSON（`jingyu-json-v1`：键排序、紧凑、UTF-8）的 SHA-256。
- Schema 由注册表生成，`schemas/` 下的文件是导出物，不手写。

## 5. 单位、坐标与颜色

- 长度米、角度度，字段名不带后缀；其他单位写进字段名（`power_w`、`lens_mm`）。
- 右手系、Z 向上、XYZ 欧拉角；物体原点在底面中心，平面以中心为原点。
- 场景里的颜色是 sRGB 十六进制；进入渲染前转线性。材质配方（`Recipe`）内部全部是
  线性值。

（`jingyu/conventions.py` 是唯一定义处，`get_guide` 原样返回给模型）

## 6. 生成器

景语收集生成器，不收集资产。新形状、新表面首先考虑能否用已有生成器的参数表达；
不能时再加一个生成器，而不是加一个模型文件。

- `run` 是纯函数：同样的参数永远得到同样的结果，不读文件、不看时间、不用全局随机。
  需要随机时由参数给种子。
- 每个参数都有 `description`；必填当且仅当没有默认值；数值给出范围。（注册时强制）
- 参数面向创作意图（光泽、抛光、腹部位置），而不是渲染器内部通道。映射在生成器里完成。
- 单个参数表达不了的约束写进 `check`，返回带参数名的问题，校验会把它定位到字段。
- 每个生成器至少带一个示例；几何算子的默认参数和全部示例都必须生成闭合流形、外法线、
  体积为正的网格。（测试）
- 加完生成器运行 `python -m jingyu.reference --write` 更新目录和 Schema。

## 7. Blender 封装

- 只走 `bpy.data`，不用依赖窗口和选择状态的 `bpy.ops`。
- 版本差异只能出现在 `blender/compat.py`；其他模块不判断 Blender 版本。最低支持 4.2。
- worker 不论成败都写响应文件；Blender 的全部输出进 `blender.log` 并随候选保存。
- 主机只信任响应文件，并检查响应声称的输出确实存在。

## 8. 候选与文件

- 每次渲染产生新的候选；候选发布后不再修改。改图 = 改场景 + 再渲染。
- 先写进 `candidates/.staging/`，检查齐全后用一次原子重命名发布；中途失败清理暂存。
- 回执记录每个文件的 SHA-256；`get_candidate` 每次重新校验，缺文件、多文件或内容不符都会报出。
- 路径一律用 `pathlib`，不写死个人路径。工具接受的路径必须落在工作区内（解析符号
  链接后再判断），否则报 `workspace.path_escape`。CLI 命令行上给的场景文件是普通本地
  路径。

## 9. 可复现

- 渲染固定采样种子；回执记录景语版本、Blender 版本、引擎、设备、分辨率、采样和耗时。
- 同一场景的规范化结果和哈希在任何机器上都相同。

## 10. 依赖

- 运行时依赖固定版本（`pyproject.toml`），尽量少：目前只有 jsonschema 和 Pillow。
- MCP、bpy 是可选附加项；缺失时给出安装命令，而不是导入错误。
- 运行时不联网。

## 11. 测试与门禁

提交前在本地跑：

```bash
ruff check . && ruff format --check .
mypy
python -m jingyu.reference --check
python -m pytest -q
```

- 测试标记：`blender`（需要 Blender 运行时）、`gpu_engines`（EEVEE / Workbench）、
  `mcp`（需要 mcp 附加项）。没有 Blender 时 `blender` 测试跳过；**找到了 Blender 但它
  坏了，测试必须失败**，不能用跳过掩盖。
- CI（`.github/workflows/ci.yml`）：静态检查与生成物新鲜度；Linux、Windows、macOS 上
  Python 3.11–3.14 的单元测试；Linux 上用 bpy 5.0.1 跑真实渲染并上传示例图；wheel 隔离
  安装冒烟。
- 修 bug 先写能复现它的测试。

## 12. 宪法

- 《景语视觉宪法》在 `docs/视觉宪法/` 和包内 `jingyu/resources/constitution/` 各有一份，
  两份逐字节相同。（测试）
- 条款 id（如 `J1.03`）发布后不复用、不改义；修宪升版本号，旧版本保留。
- 宪法用来提问，不作为验收理由；机器能判定的硬性失败放进校验和检测，不写成条款。

## 13. 提交

- 直接提交到 `main`。提交信息用一句话概括结果。
- 用户可观察的变化记进 `CHANGELOG.md`。
