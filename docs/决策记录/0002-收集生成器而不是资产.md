# ADR-0002 收集生成器，而不是资产

- 状态：已采纳（2026-09-26），修正了早先“先建资产库”的设想

## 背景

一把椅子的模型文件，相当于音乐里一段现成的旋律。资产模式下，“微小的差异”意味着多一个
文件；题材被资产库的边界限制，还带来采样偏差和版权问题。

图像的创作性主要不在于有多少种物体。摄影师拍的大多是很普通的东西，好坏取决于构图、
光和色彩。资源的边界限制的是“能画什么题材”，而不是“能画得多好”。

## 决定

收集像音符一样有限、可以组合、带参数的原语：几何算子和材质族。一件器物是一行参数，
差异再小也只是数值不同。资源建设顺序：

1. 几何算子与材质族（地基）；
2. 风化层（磨损、积尘、氧化、指纹），它决定照片感；
3. 最后才用 CC0 资产补有机物等缺口，比如人物。

## 后果

- 第一波的验收图 `examples/scenes/eight-vessels.json`：杯、碗、花瓶、酒瓶、玻璃罐、
  铜罐、银瓶、玻璃杯全部来自同一个 `vessel` 算子，八行参数。
- 生成器必须是纯函数、参数自描述、可在主机上测试（见 [工程规范](../工程规范.md) 第 6 节）。
- 干净的生成器输出缺少时间痕迹，看起来像产品渲染；风化层是下一步的重点。
