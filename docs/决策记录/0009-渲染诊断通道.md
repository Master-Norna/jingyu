# ADR-0009 渲染诊断通道：光照与颜色测量

- 状态：已采纳（2026-09-26）

## 背景

第二次实测（清晨窗边静物）里，模型的大部分功夫花在“看不清”上：橙子渲染出来是桃色，
它只能凭感觉判断是不是材质颜色的问题；光带落在桌上哪里，要自己用太阳方位角和窗洞位置
去算；房间没封顶，天光从上面灌进来把墙照冷，没有任何提示；而镜头背后的墙被报成
“出画”，真正的问题反而被淹没。这些不是某个工具的毛病，而是渲染结果只有一张图，
图里的原因没有被测出来。

## 决定

- 每次渲染附带**光照诊断通道**：在 Blender 里用场景自己的射线求交，对相机看到的每个
  采样点求出哪些灯直接照到它、背光、或被哪件物体挡住，结果和图像、ID 遮罩一样写进
  不可变候选（`light_mask.png`、`light_map.json`）。
- 颜色用**测量**回答：定位与布局把渲染出的平均颜色和材质颜色并排给出，并算出色相、
  饱和度、明度的偏移。
- 画面检查以诊断为依据：只报取景范围内被挡住的物体；房间开窗却向上敞开时报
  `light.open_to_sky`。
- 警告可以声明为有意为之：`attached_to` 说明物体有意相接，`accept_warnings` 在场景或
  物体上接受某类警告。只有警告能接受。

## 后果

- 每次渲染多约 0.3 秒和两个小文件；此前的候选没有光照通道，相关工具报
  `candidate.missing_pass`，重渲一次即可。
- 面光按中心点计算，不测半影；天光不算作灯。诊断回答“哪盏灯到了没有”，亮度仍以
  渲染图为准。
- 取景范围按包围盒判断，在画框角上偏保守（可能把刚好在角外的物体算作在内）。
