# ADR-0007 光照环境是生成器

- 状态：已采纳（2026-09-26）

## 背景

第一次用模型实测（清晨窗边静物）时，模型只有点光、聚光、面光和一个纯色世界可用。它拿
一盏近乎水平的面光去模仿晨光，结果光没有方向，投影出不来，整张图像产品渲染。问题不在
某一盏灯的参数：自然光是一个整体，太阳方向、天空颜色、阳光色温、阴影软硬和地面反光
必须彼此一致，一个个手工拼几乎不可能拼对。

只加一个 `sky` 字段能修好这张图，却修不好下一张阴天、黄昏或雪地的图。

## 决定

- 把“场景外面的光”做成第三类生成器：**环境族**，与几何算子、材质族共用
  `GeneratorDef`。场景里写 `world.environment = {"family": ..., 参数}`。
- 环境族只暴露人描述天气和时间时会用的量，在内部一起推出所有必须一致的渲染量，输出与
  渲染器无关的 `EnvironmentRecipe`（均匀光、天空、太阳、地面）。
- 第一批：`daylight`（黎明到黄昏、晴到阴、窗外进来的光）和 `uniform`（影棚、纯色）。
- 天空用 Blender 的物理散射模型，关掉太阳圆盘，另配一盏方向和颜色一致的太阳灯；亮度
  标定在实测基础上，让天光大约是正午直射光的三分之一。

## 后果

- 新的自然环境（月夜、雾、室内夜景）是新增一个生成器，Schema、目录和文档自动跟上。
- 旧的 `world.color` / `world.strength` 保留，没有 `environment` 时等同于 `uniform`，
  现有场景不受影响，`jingyu.scene.v1` 不升版本。
- 标定常数（天空亮度、阴天亮度）写在 `environments/families.py`，换渲染器或 Blender
  改了天空模型时要重新测量。
