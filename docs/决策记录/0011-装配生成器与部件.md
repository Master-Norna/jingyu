# ADR-0011 装配生成器与部件

- 状态：已采纳（2026-09-26）

## 背景

第二、三次实测里，一张桌子要用 5 个 `box` 拼，桌腿坐标手算；侧墙要绕 z 轴转 90°，窗洞
位置自己换算成世界坐标；房间要四面墙加一块天花板，每块都要摆。这些是重复劳动，也是
出错的主要来源。另一方面，一件东西常常不止一种材质：桌面是木头、桌腿是铁，墙是灰泥、
窗是玻璃。纯 `box` 的锋利直角也是画面“像电脑做的”的第一个破绽。

## 决定

- **装配也是生成器**：`room`、`table`、`chair`、`shelf` 和带窗框、玻璃的 `wall` 都是
  一次生成器调用、一个物体，参数按人描述家具的方式给：总尺寸、板厚、腿粗、内缩。房间
  的门窗按墙的名字（back / front / left / right）和沿墙位置给出，不再旋转、摆放墙体。
- **部件**：装配的网格由若干具名部件组成（桌面与桌架，墙、地板、天花板、窗框、玻璃），
  每个面记着自己属于哪个部件。物体的 `part_materials` 可以给每个部件单独的材质；没写的
  部件用物体的 `material`，或生成器为它声明的默认材质（窗玻璃默认是薄玻璃）。
- **ID 遮罩按部件编码**：每个面带一个面属性，遮罩里的每个序号对应“物体加部件”，定位
  能说出“这是桌子的桌面，改 `/objects/1/part_materials/top`”；布局仍按物体汇总，并列出
  各部件的像素占比。光照诊断和求解器按被击中的那个面的材质判断是否透光。
- **倒角**：`box` 和所有装配都可以圆角，圆角网格在纯核心里生成，物理检查和渲染看到的
  是同一个形状。
- **`rest_on` 从给定的高度往下落**：落到支撑物在它下方最近的表面；下方没有表面时（比如
  给的高度是 0），才像以前一样从高处落到最上面的表面。于是书放在架子哪一层、东西放在
  房间地板上都符合直觉，而“写 0 让景语算高度”的旧写法结果不变。
- **房间的原点在地板表面**：地板板在原点下方，东西 `rest_on` 房间就站在地板上。这是
  “立在原点上”规则唯一的例外，与平面“以中心为原点”并列写进约定。
- **薄玻璃**：窗玻璃这类薄片不折射，光线直接穿过、阴影也透光，只保留表面反射。实心
  玻璃仍然折射。原因是渲染器几乎采样不到“太阳折射穿过玻璃”这条焦散光路，窗户会把
  房间挡暗。

## 后果

- 场景短了很多：示例 `furnished-room.json` 的房间、桌、椅、书架各是一行生成器调用。
- `rest_on` 的语义改变只影响“给定高度落在支撑物两层表面之间”的写法，这正是以前会
  得到反直觉结果的情况。
- 部件名是生成器参数表的一部分，发布后不改名；`list_generators` 和生成器目录列出每个
  装配的部件与默认材质。
- 布尔运算仍未提供：主机侧没有可靠的纯 Python 布尔，而主机和渲染器必须看到同一个
  形状。门窗洞这类最常见的“挖洞”由墙和房间的生成器直接做出。
