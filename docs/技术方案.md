# 技术方案

> 本文是方案的当前版本（2026-09-26）。已定的决定见 [决策记录](决策记录/README.md)，
> 现有实现见 [架构](架构.md)。

## 定位

景语是一套给模型使用的生图工具与工作流：可控、一致、可编辑。接入的模型自带视觉能力，
它写场景、看图、指出问题、改场景、再渲染。

核心判断：

1. **生成器 = 三维场景 + 虚拟相机。** 光影、透视和遮挡由渲染器物理地保证同源，全局统一
   有了地基。不接扩散模型，保持轻量。
2. **收集生成器，不收集资产。** 几何算子和材质族像音符一样有限、可组合、带参数；一件
   器物是一行参数。图像的好坏主要取决于构图、光和色彩，而不是物体种类的多少。
3. **可编辑、可定位比一次出好图更重要。** 模型知道不对劲却说不出哪里不对时，只需要指出
   位置，工具把位置翻译成场景里可以修改的字段。
4. **立宪先行。** 视觉宪法用来提问，保证多轮迭代不跑题；不作为验收理由。

## 工作流

```
画面意图 ─→ 场景描述 ─→ 校验 ─→ 预览渲染 ─→ 看图（整体、眯眼、明暗、镜像、比较）
                ↑                                   │
                └──── 改参数 ←── 定位 / 布局 / 减法审查 ←┘
                                                    │
                                              正式渲染（final）
```

每次渲染都是新的不可变候选，随时可以回到任何一版比较。

纹理和后处理只用经典图形学算法，CPU 可跑；神经网络算法即使很小，也会把权重和推理环境
带回来，与轻量的前提冲突，如确有必要只作为可选插件。

## 风险

- **题材边界。** 有机体仍然难以参数化：人物、动物、近景的花叶要靠资产补缺；树和草是远景
  尺度。
- **主机侧生成的开销。** 地形、草地、树在主机上用纯 Python 生成，大场景的校验和构建要几秒。
- **渲染耗时。** CPU 路径追踪的正式图在分钟级；有 GPU 时秒级。预览档（半分辨率、16 采样）
  加常驻 worker，迭代保持在一两秒。OptiX 第一次遇到环境光遮蔽节点时要编译几分钟内核。
- **程序纹理的方向。** 一种材质只有一个纹理方向，同一物体不同方向的部件要用两种材质。
